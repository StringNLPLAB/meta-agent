# OpenCode and local model inference

Use this reference when the experiment owner selects OpenCode or a locally deployed coding model. The outer coding agent translates natural-language endpoint, model, resource, and review requirements into the configuration below. The experiment owner need not create a contract, edit provider JSON, or launch the review loop manually. The general training workflow, one-time EAU setup summary, per-run component discovery, and execution gate remain the same as for Codex.

## Model server and CLI

The adapter targets **OpenCode 1.19.3**, whose `run` command accepts a prompt on stdin and emits events with `--format json`. OpenCode 2.x has a different configuration interface and is not covered by this adapter. Verify the installed version before claiming compatibility. See the [versioned OpenCode CLI source](https://github.com/anomalyco/opencode/blob/v1.19.3/packages/opencode/src/cli/cmd/run.ts) and [provider documentation](https://opencode.ai/docs/providers/).

The local server must expose an OpenAI-compatible API with chat completions, tool calls, and enough context/output capacity for the skill, evidence reads, response schema, and decision. An ordinary text-completion endpoint alone is insufficient for the coding agent's tool loop. Use the server's actual served model ID; it may differ from the Hugging Face repository name. The model server and OpenCode's per-request CLI process have separate lifetimes.

For [RecursiveSI/flint](https://huggingface.co/RecursiveSI/flint), the official model card documents an SGLang deployment at `http://localhost:30000/v1`, served model ID `flint`, with `unused` as the example API key. Its deployment instructions include tool-call and reasoning handling; preserve those requirements when starting the server. Inspect the selected host and official serving recipe before allocating resources or launching weights. This adapter supplies the coding-agent connection; it does not package model weights or a GPU inference server.

The adapter preserves the API's `reasoning_content` across tool turns. For served model IDs ending in `flint`, it also uses the model card's temperature `1.0` and top-p `0.95`; keep top-k `20` in the serving configuration. Other served models use OpenCode's model defaults. Context and output limits must fit the actual server; the adapter's conservative defaults are not a claim about a model's maximum capacity.

If the server is already running, verify that the endpoint and model are reachable from the machine that owns supervision. `localhost` refers to that machine. If credentials are required, keep the key in the declared environment variable and provide its name to the runner. Do not put a token in the URL, natural-language prompt, contract, or saved command arguments.

## Runner configuration generated by the outer agent

For a new local experiment, use the [repository runtime](../../../../runtime/README.md) to perform discovery and own the trainer and continuing OpenCode supervisor. It accepts the backend flags below in `supervisor_args`, supplies run/contract/completion bindings, and records process identities and outcomes. The [minimal τ³-bench example](../../../../examples/tau3_minimal/README.md) can generate this launch configuration. The outer agent derives all settings from the request; the experiment owner need not write JSON or launch processes.

The following lower-level example applies when another verified host job system already owns training. These paths, budgets, and limits are illustrative; reuse the experiment's inspected recipe and authorization:

```bash
SKILL_DIR=/absolute/path/to/meta-agent/.agent/skills/meta-agent
TRAIN_ROOT=/absolute/path/to/training-checkout
RUN=RUN

SUPERVISE=(python3 "$SKILL_DIR/scripts/supervise.py"
  --root "$TRAIN_ROOT" --run "$RUN"
  --log logs/train.log
  --trajectories reports/training_samples/RUN
  --contract reports/meta_agent_contract.json
  --backend opencode
  --opencode-base-url http://localhost:30000/v1
  --agent-model flint
  --opencode-context 32768 --opencode-output 8192
  --every-steps 20 --every-seconds 600
  --max-calls 30 --stop-step 200 --idle-timeout 1800
  --export-atif)

"${SUPERVISE[@]}" --once
```

With the lower-level worker, complete discovery first, then launch the authorized trainer and place the command without `--once` under the verified host job owner, as described in [supervision](supervision.md). With the repository runtime, it performs that sequence and owns trainer termination on failure; omit this example's `--stop-step` and let the trainer's exit trigger final review. Neither path starts an inference server. Select progress parsing, observation windows, timeouts, and stop conditions from the inspected training project.

Options specific to backend selection:

| Option | Meaning |
|---|---|
| `--backend opencode` | Use the built-in OpenCode adapter; the default remains `codex`. |
| `--agent-model flint` | Exact model ID exposed by the local server. Codex can also use this option to select its model. |
| `--opencode-base-url http://localhost:30000/v1` | OpenAI-compatible base URL, including its API prefix. Required for OpenCode. |
| `--opencode-api-key-env LOCAL_MODEL_API_KEY` | Optional name of an existing environment variable containing the server credential. |
| `--opencode-context 32768` | Context capacity declared to OpenCode; match the model server's supported limit. |
| `--opencode-output 8192` | Maximum model output tokens; leave enough context for instructions and evidence. |
| `--opencode-command '["/absolute/path/to/opencode"]'` | Optional literal argv for the OpenCode executable; defaults to `["opencode"]`. |

The pre-existing `--agent-command` interface remains available for custom agents. It expects the runner's stdin/JSON-response protocol and must supply its own tool restrictions. Do not combine it with `--backend opencode`. Commands are literal argv arrays rather than shell programs.

## Per-request behavior and boundaries

Each due discovery/review/reconciliation/final call starts a fresh OpenCode session. The adapter generates isolated provider and agent settings for that request, binds both regular and small-model selection to the chosen local endpoint, and supplies the actual skill text and response schema. It does not reuse an interactive OpenCode session or fall back to a cloud model. Prior decisions, evidence, and pending predictions are retained in the runner's existing records rather than depending on CLI conversation history.

Runner calls expose file-reading tools (`read`, `glob`, and `grep`); edit, shell, network-fetch, and task-delegation tools are not enabled. Read scope includes the training checkout, skill, and explicitly bound evidence/record locations, including logs and samples outside the checkout. These are coding-agent permission settings, not an OS-level filesystem sandbox. The experiment contract still determines which readable sources may inform a decision. Use host isolation when a source must be inaccessible to the CLI process itself.

The model returns one JSON object matching the supplied schema. A malformed response, tool failure, or inference timeout does not authorize a training write. The controller records the call and uses the existing reconciliation/discovery retry rules. A schema-valid decision is subject to the same review validation, preregistered prediction, authorized operation allowlist, and project gate as a Codex decision. Code changes that require a training restart still follow the declared restart plan.

The supervisor dispatches the CLI after a configured step/time boundary; the agent then reads the request's evidence paths. It does not wake itself by watching a log. See [the trigger lifecycle and OPAL comparison](supervision.md#how-a-review-invokes-the-coding-agent).

## Trajectory recording and validation

`--export-atif` records each OpenCode invocation using its saved JSON event stream, request, and parsed decision. Available messages and tool activity are exported to the same ATIF files and Harbor viewer bundles as other backends. Inspect the request's `export.json` for missing event data and partial coverage. No Codex session directory is required for OpenCode exports; hidden reasoning, missing usage, or unreported cost are not reconstructed.

Offline protocol tests exercise configuration, event parsing, structured decisions, and controller behavior without model weights. The optional real-CLI test uses OpenCode 1.19.3 with a localhost mock API: it checks actual evidence reads, rejected out-of-scope reads/writes, discovery and periodic review, fresh sessions, and ATIF export. Run it with `META_AGENT_OPENCODE_BIN=/absolute/path/to/opencode python3 -m unittest discover -s "$SKILL_DIR/scripts/tests" -p test_opencode_cli.py -v`.

These tests do not establish Flint's decision quality, GPU serving performance, or compatibility with every OpenAI-compatible server. A real deployment still needs an authorized, bounded discovery/review check against the selected server before claiming end-to-end model validation.
